# NEZER LAUNCHER v2.3 — обновления через GitHub Releases

**Репозиторий для обновлений:** `https://github.com/nurixde/nezer-launcher` (нужно создать, если ещё не существует). Не загружай проект в существующий `nurixde/NEZER`: там другой сайт.

## Как один раз включить обновления

1. На GitHub создай **публичный** репозиторий с точным названием `nezer-launcher` (владельцем должен быть `nurixde`).
2. Загрузите **всё содержимое папки проекта**, включая скрытую `.github/workflows/release.yml`, в корень репозитория (удобнее через GitHub Desktop или `git`). Не загружай только один ZIP как файл в репозиторий.
3. В настройках репозитория GitHub → **Settings → Actions → General → Workflow permissions** выбери **Read and write permissions** для `GITHUB_TOKEN`, если это разрешено настройками аккаунта.
4. Создай и отправь тег `v2.3.0` (должен совпадать с `package.json`):
   ```powershell
   git tag v2.3.0
   git push origin v2.3.0
   ```
   Перед этим нужен обычный коммит всех исходников в репозитории.
5. GitHub Actions запустит сборку на Windows и создаст **Release** с `.exe`, `latest.yml` и `.blockmap` (не меняй названия файлов). Открой Actions и Releases: только успешный выпуск означает, что сервер автообновлений действительно доступен.
6. Скачай `.exe` из этого Release и **один раз установи** поверх прежнего приложения. Запуск `START-LAUNCHER.bat` предназначен для разработки и **не умеет обновляться** через NSIS.
7. Для следующих выпусков изменяй `package.json` → `version` (например, `2.3.1`), коммить изменения и отправляй тег `v2.3.1`. В установленной программе нажми **Настройки → Проверить обновления → Скачать → Перезапустить и установить**.

В будущих релизах сохраняй те же `appId`, `productName`, `nsis.guid`, владельца и имя репозитория. Не делай приватным репозиторий автообновлений: обычный публичный клиент не должен получать GitHub-токен.

**Что проверено:** структура архива, базовые локальные тесты и настройки публикации. **Не проверено:** сборка Windows в GitHub Actions, фактический выпуск и живое автообновление; это зависит от твоего репозитория и первой успешной сборки. Установщик пока не подписан сертификатом подписи кода; Windows SmartScreen может показать предупреждение о неизвестном издателе. Для публичного распространения рекомендуется подписание установщика.
